# Writing great skills

A skill makes the process predictable, not the output identical.

1. Give it one clear invocation purpose. Keep the description to genuinely distinct triggers; do not duplicate body text.
2. Make each ordered step finish with a checkable completion criterion. Put shared action in the main file and disclose optional reference behind a precise link.
3. Keep one source of truth for each rule. Remove stale, duplicated, or default-behavior prose.
4. State authority boundaries and safe completion conditions. A baseline skill must not imply cross-repository, credential, or remote-delivery authority.
5. Test the skill against a representative task and revise only where its instructions change the process materially.

Prefer a small number of focused skills over a broad, overlapping catalog.
